# Общий подход для приложений пользователя

Связка: чат/агент → GitHub (исходники + Actions + Releases) → обновление на телефоне. Не хранить постоянные каталоги приложений и коллекции APK на ПК.

- Отдельный репозиторий на каждое приложение. В Git — код, тесты, публичные лицензии, AGENTS.md и workflow. В Releases — app.apk, source.zip и update.json.
- Секреты подписи хранятся в защищённых GitHub Actions secrets каждого репозитория. Исходный ключ существующего приложения переносится без замены. Его отпечаток фиксируется в проверке выпуска.
- Токены GitHub никогда не входят в приложение. Публичный release manifest доступен телефону без авторизации. Локальный доступ агента при необходимости — системный credential helper; значение токена не выводить.
- Обновление приложения — отдельная кнопка в настройках, только по запросу пользователя. Проверки: HTTPS и разрешённые CDN, размер, SHA-256, applicationId, версия, сертификат. Установка подтверждается Android. Ошибка/отмена не меняет пользовательские данные.
- Повышать versionCode, сохранять applicationId и подпись, выполнять неразрушающие миграции. Никогда не требовать удаления приложения для штатного обновления.
- На GitHub ничего из банковских данных, приватных ключей, .env, keystore-файлов, пользовательских БД, локальных cache или конфигурации чужих проектов.
- Сначала полностью проверить перенос, cloud-сборку и доступность релиза, затем удалять локальные исходники и артефакты. Не удалять общие инструменты или проекты другого активного чата.
- Реализация для копирования: .github/workflows/android-release.yml и scripts/cloud-release.cjs. Для другого приложения заменить repo, сертификат, способ восстановления его исходного keystore и имя задачи сборки; не использовать Money-ключ для нового приложения.

Формат update.json: versionCode, versionName, apkUrl, sha256, size. Увеличение версии без опубликованного APK не является выполненным обновлением.
